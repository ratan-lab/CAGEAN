# data_prep

Four numbered scripts to reproduce the full data pipeline from raw public data to
model-ready numpy arrays.

---

## Prerequisites

```bash
conda activate cagean   # environment.yml in repo root

# Optional binaries (not conda-installable; place in $PATH or ~/bin):
#   bigWigToBedGraph  https://hgdownload.soe.ucsc.edu/admin/exe/
#   liftOver          https://hgdownload.soe.ucsc.edu/admin/exe/
#   hg38ToHg19.over.chain  (download alongside liftOver)
```

---

## Scripts

### `01_scan_pqs.py` — Download PQS BED from epiG4NN data repository

Downloads `PQS_padded.bed` (2,105,836 sites) from the epiG4NN Zenodo deposit
(DOI: 10.5281/zenodo.8144456). The PQS set was generated by Korsak et al. (2023)
using a custom regex-based hg19 scan covering canonical, bulged, and irregular G4
motifs. We use their pre-computed file directly.

```bash
python data_prep/01_scan_pqs.py --out pqs/PQS_padded.bed
```

Requires `wget` or `curl` on PATH. Alternatively, download `PQS_padded.bed`
manually from https://zenodo.org/records/8144456 and place it at the output path.

### `02_extract_epi_signal.py` — BigWig → per-chromosome numpy arrays

Extracts epigenomic signal from a BigWig over each PQS window (1000 bp, 1 bp
resolution) and writes per-chromosome arrays. Also writes a one-hot sequence array
(`{chrom}_seqs.npy`) on the first run and a coverage mask
(`{chrom}_covered_{mark}.npy`, True where signal is non-zero) used to restrict
cross-cell evaluation to sites with non-zero epigenomic signal in the target cell type.

```bash
# Run once per mark per cell type
python data_prep/02_extract_epi_signal.py \
    --pqs_bed pqs/PQS_padded.bed \
    --bigwig  /path/to/h3k4me3.bigwig \
    --mark    h3k4me3 \
    --out_dir data/a549
```

Output per chromosome: `{chrom}_seqs.npy` (N,4,1000) int8, `{chrom}_epi_{mark}.npy`
(N,1000) float32, `{chrom}_covered_{mark}.npy` (N,) bool.

One-hot encoding: ATCG order (A=channel 0, T=1, C=2, G=3).

### `03_make_labels.py` — ChIP-seq signal → G4-occupancy labels

Two modes depending on the assay type:

**`--bigwig` (G4P ChIP-seq, A549 / HEK293T / HeLa.S3):** extracts mean per-base signal
over each 1000 bp window. Binarization at Q90 of non-zero signal happens at training
time — this script writes raw continuous signal so any threshold can be applied.

**`--bed` (BG4 narrow-peak BED, K562 / HepG2 / H9 ESC):** writes 1.0 for any PQS
window that overlaps a BG4 peak, 0.0 otherwise.

```bash
# G4P continuous signal
python data_prep/03_make_labels.py \
    --pqs_bed pqs/PQS_padded.bed \
    --bigwig  /path/to/g4p_signal.bigwig \
    --out_dir data/a549

# BG4 binary peaks
python data_prep/03_make_labels.py \
    --pqs_bed pqs/PQS_padded.bed \
    --bed     /path/to/k562_bg4_peaks.bed \
    --out_dir data/k562_bg4
```

Output per chromosome: `{chrom}_labels.npy` (N,) float32.

### `04_normalize.py` — z-normalization for epiG4NN TF baseline only

**This script is not needed for CAGEAN.** CAGEAN's epigenomic stem uses InstanceNorm1d,
which normalizes each sample at inference time using its own statistics. No pre-normalization
is required, and applying it would be redundant.

This script exists for the epiG4NN TF baseline (Tables 1–2), whose batch normalization
uses training-set running statistics and requires z-normalized input for fair cross-cell
evaluation. Run it in the `cagean_tf` environment after activating:

```bash
conda activate cagean_tf
python data_prep/04_normalize.py \
    --a549_train_dir data/a549 \
    --mark           h3k4me3 \
    --params_out     data/norm_params_h3k4me3.json \
    --apply_to       data/hek293t data/k562_bg4
```

The normalization parameters (mean and std computed on A549 training chromosomes) are
saved to a JSON file. These must be archived alongside the TF model weights; a reader
who recomputes them will get slightly different cross-cell AUPRC even with identical
checkpoints.

## Data sources (`data_manifest.csv`)

`data_manifest.csv` lists every file used in the paper with its accession, source, and
direct download URL. Key points:

| Cell type | G4 labels | Source |
|-----------|-----------|--------|
| A549 | G4P ChIP-seq (continuous signal) | GEO GSE133379 |
| HeLa.S3 | G4P ChIP-seq (continuous signal) | GEO GSE133379 |
| HEK293T | G4P ChIP-seq (continuous signal) | GEO GSE133379 |
| HepG2 | BG4 consensus peaks | GEO GSE145090 |
| K562 | BG4 high-confidence peaks + signal | GEO GSE107690 / GSM2876090 / GSM2876093 |
| H9 ESC | BG4 consensus peaks (hg38→hg19 liftover) | GEO GSE161531 |

Epigenomic marks (H3K4me3, H3K27ac, ATAC-seq) come from ENCODE for A549, HeLa.S3,
HepG2, HEK293T, and K562. H9 ESC marks come from Roadmap Epigenomics (E008); DNase-seq
is used as a chromatin accessibility proxy because Roadmap E008 has no ATAC-seq.

All ENCODE files used GRCh38 signal tracks and were lifted to hg19 using UCSC liftOver
with the hg38ToHg19.over.chain chain file. ENCODE files already in hg19 are marked
`liftover_to_hg19 = no` in the manifest.

TSS annotations for `eval_stratified.py` were derived from UCSC RefFlat
(`refFlat_hg19.txt.gz`) by taking each unique TSS coordinate and expanding ±2 kb, then
merging overlapping regions with pybedtools. The resulting `tss_2kb_hg19.bed` is
included in the Zenodo archive.

## Assembly note

All models and evaluations use **hg19 (GRCh37)**. Files that arrive in GRCh38 (most
ENCODE signal tracks, H9 ESC BG4 peaks) are lifted over before processing. The liftover
is performed with `liftOver` and the `hg38ToHg19.over.chain` chain file; unmapped
intervals are discarded.
